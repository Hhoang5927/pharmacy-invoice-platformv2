# 1. Overview

## Purpose

The Validation Module evaluates the extracted invoice against all approved Business Rules.

Its objective is to ensure the extracted data is complete, consistent, and compliant before entering the Human Review stage.

Validation shall not modify business data.

Validation shall only detect, classify, and report issues.

---

## Responsibilities

The Validation Module shall:

- Execute Business Rules
- Validate required fields
- Validate data types
- Validate business constraints
- Validate cross-field consistency
- Calculate validation summary
- Determine review requirement
- Generate validation report

# 5. Validation Categories

## Required Field Validation

Examples

- Invoice Number
- Invoice Date
- Supplier
- Purchase Items
- Medicine Name
- Quantity
- Unit Price

Missing required fields shall generate an Error.

---

## Format Validation

Examples

Invoice Number

Date Format

Currency Format

Tax Code

Batch Number

Expiry Date

---

## Numeric Validation

Examples

Quantity > 0

Price > 0

VAT ≥ 0

Total ≥ 0

---

## Cross-field Validation

Examples

Subtotal + VAT = Total

Invoice Total = Sum(Line Totals)

Expiry Date > Manufacture Date

Purchase Items ≥ 1

---

## Business Rule Validation

Business Rules shall be loaded from Pack 01.

Examples

BR-001

BR-002

BR-003

...

Validation Engine shall never hardcode business logic.

# 6. Severity Levels

Every validation result shall have one severity.

INFO

No action required.

WARNING

Review recommended.

ERROR

Correction required.

CRITICAL

Processing cannot continue.

---

# 7. Validation Result

Each validation result shall contain:

- Rule Identifier
- Rule Name
- Severity
- Target Field
- Current Value
- Expected Condition
- Result
- Message

---

# 8. Validation Report

Overall Status

Executed Rules
