# 1. Purpose

This document defines the standard project structure for the Pharmacy Invoice Automation Platform.

The objective is to establish a predictable and maintainable repository layout.

Every source file shall follow this structure.

No module shall create arbitrary directories.

---

# 14. Dependency Rules

Allowed

Presentation

↓

Application

↓

Domain

↓

Infrastructure

Forbidden

Infrastructure → Presentation

Infrastructure → UI

Domain → Infrastructure

Circular dependencies are prohibited.

---

# 15. Import Rules

Imports shall follow

Standard Library

↓

Third-party Libraries

↓

Internal Packages

↓

Relative Imports

Wildcard imports are prohibited unless explicitly justified.

---

# 16. File Organization

Every source file shall have a single responsibility.

Files exceeding the agreed complexity threshold should be refactored.

Business logic shall not be implemented in UI components.

---

# 17. Naming Rules

Directories

lowercase

Example

review

automation

validation

Files

PascalCase for classes.

camelCase for utility modules.

kebab-case for configuration files.

---

# 18. Acceptance Criteria

The project structure is accepted when

✓ Repository layout is standardized.

✓ Every module has a defined location.

✓ Dependency rules are respected.

✓ Shared code is centralized.

✓ Documentation remains synchronized with implementation.
