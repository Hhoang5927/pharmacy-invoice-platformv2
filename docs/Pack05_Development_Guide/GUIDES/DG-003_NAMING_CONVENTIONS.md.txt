# 1. Purpose

This document defines the naming conventions for the Pharmacy Invoice Automation Platform.

Consistent naming improves readability, maintainability and collaboration.

These rules apply to both human developers and AI coding assistants.

---

# 2. General Principles

Names shall

- Be descriptive.
- Be consistent.
- Avoid abbreviations unless widely accepted.
- Represent business meaning.
- Follow the project language standard (English).

Avoid generic names such as

data

item

object

temp

value

result

manager

helper

---

# 3. Directory Names

Directories shall use

lowercase

Examples

review

validation

invoice

# 4. File Names

TypeScript

camelCase

# 5. Class Names

Classes shall use

PascalCase

Examples

ValidationEngine

AutomationExecutor

OCRProcessor

ReviewManager

---

# 6. Interface Names

Interfaces shall use

PascalCase

Do not prefix with "I".

Correct

InvoiceRepository

OCRProvider

AutomationDriver

Incorrect

IInvoiceRepository

IOCRProvider

---

# 7. Function Names

Functions shall use

camelCase

Examples

validateInvoice()

extractSupplier()

calculateTotal()

generateReport()

submitInvoice()

---

# 8. Variable Names

Variables shall use

Examples

invoiceNumber

supplierName

purchaseItems

executionReport

Avoid

obj

val

data1

# 24. Acceptance Criteria

Naming conventions are accepted when

✓ Naming is consistent.

✓ Business terminology is preserved.

✓ Files follow standard naming.

✓ APIs follow REST conventions.

✓ Database objects are predictable.

✓ AI-generated code follows identical conventions.
